# MorphDemo

*Specification v1.1 (2026-09-23): adds `ENVIRONMENT.json`, working conditions and the self-decompression clarification. The creative task and all output requirements are unchanged.*

Create three original real-time audiovisual demos under strict executable-size constraints.

All three demos belong to the same project and must be completed in this run.

## Runtime environment

The final programs will be run on the following system:

- NixOS, x86-64
- NVIDIA GeForce RTX 5090
- NVIDIA graphics driver available
- CUDA available
- OpenGL and Vulkan available
- Audio output available through the system audio stack
- 1920×1080 display target

You may use system libraries that are already present in the supplied environment.

The supplied `ENVIRONMENT.json` lists the actual loader, runtime libraries, display setup and build tools of this machine. Read it instead of guessing.

The final programs must not require downloading, installing, or shipping additional runtime dependencies.

## Required executables

Produce exactly these three native Linux executables:

- `morphdemo-64k` — exactly **65,536 bytes**
- `morphdemo-16k` — exactly **16,384 bytes**
- `morphdemo-4k` — exactly **4,096 bytes**

The sizes above are exact file sizes on disk, not upper limits.

Every executable must independently satisfy the complete task described below.

Padding is allowed if necessary to reach the exact required file size, but each executable itself must remain a valid runnable native Linux executable.

The final artifacts may not be shell scripts, interpreted source files, bytecode wrappers, archives, launchers, or thin wrappers around another program that performs the production.

Self-decompression is allowed: an executable may contain its own compressed code and data and unpack it at runtime, in memory or into an anonymous in-memory file that it then executes. The unpacking must be done by code inside the executable itself. Invoking an external unpacker, shell or other program on the system is not allowed.

## Working conditions

There is no limit on development time, tokens, cost or iterations. Work until the result is as good as you can make it.

## Creative brief

Theme:

**FROM NOISE TO ORDER**

Interpret the theme freely.

Do not recreate an existing demo, artwork, game, film scene, or supplied visual reference.

Each production should have its own visual identity and should feel like a coherent audiovisual work rather than a collection of unrelated technical effects.

The three executables may share concepts, code, visual language, music systems, or production ideas, but each executable must be a complete standalone production that satisfies all requirements independently.

Each demo must have a recognizable progression:

1. **Emergence** — begin from a sparse, unstable, chaotic, noisy, or minimal state.
2. **Transformation** — develop into increasingly structured visual and musical forms.
3. **Resolution** — arrive at a clear climax, final form, or conclusion.

These do not have to be literal separate scenes. A continuously transforming environment is valid as long as the progression is clearly perceptible.

## Required output

Each of the three executables must:

- render in real time;
- contain continuous animation;
- contain generated audio or music;
- include intentional synchronization between sound and visuals;
- contain at least three visually distinguishable phases or states;
- include meaningful transitions between them;
- display the word **MORPH** as part of the production at least once;
- run for approximately one minute;
- automatically terminate after the production;
- also allow clean termination with Escape.

The complete production of each executable must last between **50 and 70 seconds**.

Do not extend the runtime beyond this range.

## Procedural and self-contained content

Each executable must be self-contained.

Visual content must be generated by the executable at runtime.

Audio must be synthesized or generated by the executable at runtime.

Do not rely on external production assets, including:

- textures;
- image files;
- meshes or model files;
- fonts used as production content;
- prerecorded music;
- prerecorded sound samples;
- video;
- external scene or timeline data;
- external shader files;
- downloaded content;
- network resources.

Do not read production content from the filesystem at runtime.

Compact data embedded directly inside the executable is allowed.

Procedural geometry, mathematical functions, shader code, generated samples, synthesized instruments, procedural textures, compact lookup tables, and embedded parameter data are allowed.

The program may use operating-system, graphics-driver, GPU-compute, and audio interfaces available in the supplied environment.

## Behavior

Each executable must:

- start without user configuration;
- produce visible output without requiring interaction;
- produce audible output;
- run the intended sequence from beginning to end;
- avoid network access;
- avoid spawning or delegating the production to another renderer, media player, browser, interpreter, or demo executable;
- exit cleanly when finished.

A short initialization or precalculation phase is acceptable, but it should not replace the real-time nature of the production.

## Deliverables

Produce:

1. `morphdemo-64k`, exactly 65,536 bytes;
2. `morphdemo-16k`, exactly 16,384 bytes;
3. `morphdemo-4k`, exactly 4,096 bytes;
4. complete source code for all three executables;
5. everything required to rebuild all three from source using the tools available in the supplied environment;
6. a short `README.md` containing the exact build commands and a brief description of the implementation.

Only the three final executable files are subject to their exact size requirements.

Source code, build files, and documentation are not.

You may use a shared codebase, separate implementations, or a combination of both.

## Final verification

Before finishing:

- build all three final executables;
- verify the exact byte size of each file;
- run all three executables;
- verify that every production works from beginning to end;
- verify that each production lasts between 50 and 70 seconds;
- verify that each executable works independently without external production assets;
- leave all three final executables and the complete source tree in the requested output location.

Do not finish with only one or two size classes completed. The requested output is the complete set of all three executables.
