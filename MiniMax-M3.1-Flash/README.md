# MorphDemo

Three original real-time audiovisual productions under exact executable-size
limits, all of them built around one theme:

> **FROM NOISE TO ORDER**

Every production starts in a chaotic, noisy state, develops into a structured
one and ends in a clear resolution that holds the word **MORPH**.  All
visuals are generated by shaders at run time, all music is synthesised by the
programs themselves, and nothing is read from disk.

| file            | size      | production   | idea                                            |
|-----------------|-----------|--------------|-------------------------------------------------|
| `morphdemo-4k`  | 4 096 B   | **SEED**     | a dot lattice condensing out of noise into MORPH |
| `morphdemo-16k` | 16 384 B  | **ANNEAL**   | a molten landscape annealed into a word         |
| `morphdemo-64k` | 65 536 B  | **CONVERGENCE** | 65 536 particles folding into the word       |

---

## Building

Everything is built with the toolchain that is already present in the
environment: `gcc`, `binutils`, `make` and `python3`.

```sh
cd /home/morpheus/Documents/Morpheus-Produktion/Benchmarks/MorphDemo/MiniMax-M3.1-Flash
sh tools/env.sh > tools/env.mk       # locate libX11, libGL, libasound
make                                  # build all three
make check                            # verify the exact file sizes
```

`make` has `all` as its default goal, so the plain command builds the three
productions.  `make check` prints:

```
OK   morphdemo-64k 65536 bytes
OK   morphdemo-16k 16384 bytes
OK   morphdemo-4k 4096 bytes
```

A single production can be built on its own, for example:

```sh
make morphdemo-64k
```

To rebuild everything from scratch:

```sh
make clean                              # removes build/ and the executables
sh tools/env.sh > tools/env.mk
make && make check
```

The build has no dependencies beyond a C compiler, `make`, `python3` and the
runtime libraries of the machine (libX11, libGL, libasound, libc).  No
downloads, no code generators, no shader compilers.

## Running

```sh
DISPLAY=:0 ./morphdemo-64k      # runs for one minute, then exits by itself
```

* The production starts immediately, needs no configuration and shows its
  output on the display.
* **Escape** stops it at any time and it exits cleanly.
* The sound is synthesised live and played through the ALSA device of the
  system (`default`, 48 kHz, stereo).
* Each production lasts 60 seconds and terminates on its own.

## The three productions

### morphdemo-4k — SEED (4 096 bytes)

A full-screen fragment shader.  At the beginning a field of sparks drifts
through a turbulent void; the turbulence is slowly damped, the sparks snap
onto a regular lattice, and in the last third the lattice itself is rewritten
into the five letters of MORPH, one letter per beat.  The music is a drone, a
noise bed, a pulse that enters when the lattice forms and a pentatonic line
that resolves into a chord.

At four kilobytes there is no room for a window manager dialogue, a sound
library or a loader, so the file is a **self-extracting wrapper**: it carries
the production in compressed form, unpacks it into an anonymous in-memory file
(`memfd_create`) and executes that file.  The unpacking code is part of the
executable itself, exactly as the specification allows.

The payload is compressed with a small LZ codec of our own (`src/lzpack.py`).
It reaches 70 % of the original size: the production is 4 752 bytes as an ELF
and 3 323 bytes as a compressed stream, which leaves the wrapper comfortably
inside its four kilobytes.  A distance below 255 costs a single byte, 255 is the
escape that means "two more bytes follow" — most matches in a program of this
size refer to something that happened a few dozen bytes earlier, and that is
where the saving comes from.

All three productions report a missing sound device on standard error instead
of running on without saying anything, so "it played" can never be confused
with "it was silent".

### morphdemo-16k — ANNEAL (16 384 bytes)

A single fragment shader ray-marches a height field.  The field starts as a
boiling noise landscape lit by a low ember sun; the noise collapses into a
regular lattice of glowing pillars that breathes with the beat; in the last
phase everything that does not belong to the word sinks back into the ground
while the letters rise one after another and light up.  The camera swings over the
landscape and finally climbs above the word and looks down on it, which is the
only angle from which a word that lies in the ground can be read.

Because the terrain is a function `z = h(x, y)`, the ray can be marched down
in `z` and the height simply looked up, which is exact and much cheaper than
sphere tracing.

The letters are not drawn on top of the landscape — they are part of it.  Every
cell of the terrain grid that carries a letter is raised into a solid tile, and
the tiles of one letter join into a single stroke.

### morphdemo-64k — CONVERGENCE (65 536 bytes)

Sixty-five thousand five hundred and thirty-six particles live in a pair of
floating point textures (256 × 256, RGBA32F) that are updated by a simulation
shader and rendered as soft additive billboards.  At first the swarm is a
turbulent violet nebula stirred by curl noise; then it crystallises into a
slowly rotating lattice that pulses with the beat; at the end the lattice
folds into the word MORPH, letter after letter, and holds it while the music
resolves.  A two-pass bloom and a background of stars finish the picture.

Every particle belongs to one cell of the word, and the cell decides where
the particle finally lands — the letters are not drawn on top of the swarm,
they *are* the swarm.  The particles that do not belong to a letter are pushed
out of the picture and fade away while the word assembles itself.

## Implementation notes

### One clock for picture and sound

Every production runs on the **wall clock**.  The picture of a moment is drawn
with the time of that moment, and the sound device is fed exactly as much
audio as the clock has asked for since the start.  The beat of the score and
the beat of the image are therefore the same beat, the music never stutters
when the machine has to drop a frame, and the duration is exactly 60 seconds
of wall clock time.

This matters on this machine: the XWayland present path costs about 30 ms per
swap, so the productions animate at roughly 30 frames per second.  A production
that took the sound device as its only clock would stretch to nearly two
minutes; running on the wall clock keeps all three at 60.0 s.

### The sound device must not hold the picture back

The ALSA device of this machine has a period of 200 ms, and a write to it only
returns once the device has room again.  How much sound can be fed therefore
depends on how often the program asks for it: one block per picture caps the
sound at *pictures per second × block size*, and a picture is only drawn
thirty times a second.  With a block of 8192 frames the flagship production
managed five pictures per second, and with 4096 frames the middle one managed
twelve — and in both cases the music ran at half speed, which is far worse
than a low frame rate.

ANNEAL and CONVERGENCE therefore feed the device in a loop of small blocks:
they write as many 768-frame blocks (sixteen milliseconds each) as the clock
asks for, and only then draw the next picture.  The soundtrack does not depend
on the size of the block — the synthesiser is a pure function of the sample
index and carries its filter state from one block to the next — so the
rendered audio is identical either way.

SEED, at four kilobytes, has no room for that loop.  It writes one block of
2400 frames (fifty milliseconds) per picture, which is comfortably more than
its thirty pictures a second need.

### Phases

| production | noise | order | resolution |
|------------|-------|-------|------------|
| SEED (4 KiB) | 0 – 11 s drifting blue sparks | 11 – 37 s the sparks snap onto a regular lattice | 37 – 60 s the lattice is rewritten into MORPH, one letter per beat |
| ANNEAL (16 KiB) | 0 – 17 s boiling ember landscape | 17 – 38 s the noise collapses into a lattice of pillars | 38 – 60 s everything that is not a letter sinks away, MORPH rises and lights up |
| CONVERGENCE (64 KiB) | 0 – 17 s a turbulent violet nebula | 17 – 37 s a rotating lattice crystallises out of it | 37 – 60 s the lattice folds into MORPH, letter after letter, and holds |


### The word is made of the picture

In none of the three productions is MORPH a texture that is pasted over the
animation.  In SEED it is a lattice of dots, in CONVERGENCE it is the particle
swarm itself, and in ANNEAL it is the terrain: the height field raises a solid
tile on every grid cell that carries a letter, and the tiles of one letter
merge into one continuous stroke.  The camera therefore has to look down on
the word, because a word that lies in the ground cannot be read from the side.

### Notes on this driver

* The compatibility profile of this driver does not accept
  `for (a) for (b) { ... }` — the body of the outer loop needs its own braces,
  otherwise the shader fails to compile with a syntax error.
* `gl_PointCoord` returns `(0, 0)` here, so particles are drawn as small
  quads instead of points.
* The XWayland present path costs about 30 ms per swap, which is why the
  picture runs at roughly 30 frames per second.

### Small binaries

* **One translation unit per production.**  `src/demo16.c` and `src/demo64.c`
  use the shared runtime in `src/platform.c`; `src/demo4.c` is completely
  self-contained because at four kilobytes nothing can be shared.
* **No development headers.**  The environment has none, so `src/x11min.h` and
  `src/glconst.h` declare the handful of X11, GLX, OpenGL and ALSA entry
  points and structures that are needed.
* **No PLT.**  Every imported function is resolved once at start-up with
  `dlsym()`; the names live in a single blob in `.rodata`
  (`src/syms_common.h`, `src/symtab.h`).
* **One load segment.**  `src/compact.ld` puts every section into a single
  `PT_LOAD`, which removes about seven kilobytes of page-alignment padding
  that a default link would leave between the segments.  The four kilobyte
  binary uses the same trick in `src/tiny.ld`.
* **Exact size.**  `tools/exact_size.py` removes the section header table and
  the empty tail of the dynamic table and then pads the file with zero bytes
  to the exact length required.  The result is still a normal, runnable ELF.
* **No libm.**  `src/fmath.h` contains a polynomial sine and a few helpers,
  so the dependency list stays at libX11, libGL, libasound and libc.
* **A compressor that fits in the wrapper.**  `src/lzpack.py` and the matching
  decoder in `src/stub.c` are a small LZ codec: a token byte carries the
  literal count and the match length, the distance is one byte unless it
  reaches 255, and 255 means "two more bytes".  The wrapper never calls an
  external unpacker.

## Verification

```sh
sh tools/verify.sh :0
```

The script checks the exact size of each file, runs every production from
beginning to end and measures how long it takes (it has to land between 50
and 70 seconds), checks that the sound device was opened, and then runs each
production a second time and sends it an escape key to confirm that it stops
early and cleanly.

## Specification checklist

| requirement of SPEC.md | where it is met |
|-----------------------|-----------------|
| exactly 65 536 / 16 384 / 4 096 bytes on disk | `tools/exact_size.py`, checked by `make check` and by `tools/verify.sh` |
| native Linux executables, not scripts, bytecode, archives, launchers or thin wrappers | the 16 KiB and 64 KiB files are ordinary single segment dynamically linked ELF programs; the 4 KiB file is an ELF executable that unpacks **its own** compressed code into an anonymous in-memory file and executes it, which SPEC.md explicitly allows |
| real time rendering, continuous animation | ~30 fps on the XWayland present path, see *One clock for picture and sound* |
| audio generated at run time | ALSA device, every sample produced by the synthesiser of the program; no sample files |
| sound and picture synchronised | the wall clock is the master clock and the number of frames the device has accepted is the time of the picture that is being drawn |
| at least three distinguishable phases, meaningful transitions | noise → order → resolution, see the phase table |
| the word MORPH | in every production, made of the picture itself and not pasted over it |
| 50 to 70 seconds, automatic termination | exactly 60 s of wall clock, then the program exits by itself |
| clean termination with Escape | verified by `tools/verify.sh` |
| no external assets, no network, nothing read from disk at run time | every pixel and every sample is computed by the program |
| only libraries that are already present | libX11, libGL, libasound and libc — `ldd morphdemo-64k` shows nothing else |
